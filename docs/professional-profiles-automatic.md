# Professional profiles — automatic journey, 25 November 2026

The owner's latest instruction replaces the earlier manual-publication proposal: normal admission, validation, publication and matching must be automatic. The member confirms email ownership, the existing verified Payhip payment activates account access, and the member explicitly authorizes publication and matching. No owner approval is required in this path. The first real payment remains to be confirmed by the first real buyer; do not charge a test purchase.

There are fourteen sector schemas, with their own required professional fields. A common account identity is separate from the sector profile. The selected area is carried through registration, email confirmation, account portal and profile editor. Drafts without publication consent stay private. A valid authorized submission atomically updates the public snapshot and audit log. The public showcase consumes the backend feed and fills unused places from the existing 135 editorial artists. Institutions have public profiles; the photo showcase is for people and artistic groups with an authorized photograph and explicit showcase consent.

Matching is computed from published, opted-in profiles and offered/needed services. Free is local to the same normalized country with up to three results. Verified current PRO entitlements allow up to thirty results, compatible international remote collaboration, and additional professional criteria. Teaching requires compatible instruments/subjects when both profiles specify them. Reads are bounded to recent eligible snapshots. No automatic emails, hiring decisions or unsolicited contact are sent.

An admission payment does not grant PRO. `professional_entitlements` is a server-only input for verified subscription state; there is deliberately no browser or public endpoint to grant it. This release does not create PRO checkout products or connect a new subscription provider. With no verified entitlement the account remains Free; do not claim PRO billing is active merely because the matching engine supports PRO.

Owner moderation requires the existing MFA session. Removing a profile suspends automatic re-publication until the owner releases that suspension. This is an abuse-control exception, not a normal approval queue. Public feeds never include account emails, credentials or billing references. Photograph URLs are HTTPS, explicitly authorized, and not uploaded to new storage by this release.

Deployment uses existing D1 and Worker resources, additive migration 009, a saved recovery bookmark and previous Worker version, account-wide request/read/write and storage checks before mutation, and the 70% budget rule. Runtime writes are capped at 100 profile/moderation changes per UTC day, each profile JSON at 6000 bytes, and total profiles at 15000. Public reads are cached for at most sixty seconds and rate limited on cache misses. No paid service or plan is enabled.
